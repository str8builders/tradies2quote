# Porting native T2QCAL calculators to the web

Goal: the web calculator computes and labels **exactly** like the native app.
Truth is `src/t2qcal/lib/fixtures/native-reference.json`, generated by running the
real Swift code (T2QCAL repo `scripts/native-web-reference/main.swift`): for every
tool, metric and imperial, defaults plus two scaled variants — result rows, marks,
diagram values, handoffs and cuts.

Native source: `/Users/admin/Documents/Codex/2026-09-06/i-x20-2/work/t2qcal/ios/T2QCAL/T2QCAL/`
— `Models/Tools*.swift` declare each tool (fields + compute closure); geometry lives in
sibling `Models/*Geometry.swift`, `Models/*.swift` and `Engine/*.swift`. `Models/Catalog.swift`
has `Fmt`, `pos`, `rad`, `roundedInt`, `ceilInt`, `floorInt`, `n` — all ported in `native/format.ts`.

## Where a port lives

One module per Swift file: `native/<category>.ts` exports
`definitions: Record<slug, VerifiedDefinition>`. `native/index.ts` merges them; a slug
present there overrides the older hand-written web definition automatically.
Helpers for one category may go in `native/<category>-*.ts`. Do not edit any file
outside your category's module(s).

## Definition shape

```ts
definitions["concrete-slab"] = {
  title, note,                    // tool.name, tool.summary from the catalog
  diagram, sheets, showsAssembly, // from meta[slug]: diagram; sheets minus any *3d entry; showsAssembly
  fields,                         // from meta[slug].fields — key, label, default, kind, min, max, options?, visibleWhen?
  compute(values, unit) { ... }   // returns { results, marks, diagramValues, handoffs, cuts }
};
```

`kind` strings are exactly the web `FieldKind` names. Build `fields`, `diagram`, `sheets`,
`showsAssembly`, `title` (name) and `note` (summary) from `native/meta.json` at module
load (import that small JSON, keyed by slug). Never import the 1 MB reference fixture
from a module — it is test-only.

`values` arrive in the display unit (inches for imperial lengths), exactly what the
native compute closure receives (`v`), and `unit === "metric"` is the Swift `metric` flag.

## Rules for compute

- Port the Swift closure line by line. Keep the result-row order, labels, `primary`
  flags and value strings identical. Use `num`, `len`, `area`, `vol`, `deg`, `money`,
  `quantity`, `amount` from `native/format.ts` wherever Swift uses `Fmt.*`.
- Swift `"\(Int(x))"` → `String(Math.trunc(x))`; `x.rounded()` → `swiftRound(x)`;
  `Int(x.rounded())` → `swiftRound`; `.rounded(.up)` → `Math.ceil`; `.rounded(.down)` → `Math.floor`;
  `Double.ulp` → `ulp`; integer division stays integer.
- `diagramValues` must contain every native key (extra keys are allowed).
- `handoffs`: port key, label, quantity, unit, role, includeByDefault, and also
  basisFingerprint / formula / assumptions / checks when the Swift passes them
  (default `checks` are in `ToolHandoff.init`).
- `cuts`: `{ mm, count, label }` when the Swift returns `CutList.Cut`s.
- Never return `errors` for inputs the native app accepts. Where the native code
  guards with `pos()`/`max`, do the same rather than erroring.
- Do not modify `fixtures/native-reference.json`.

## Proving it

```bash
npx vitest run src/t2qcal/lib/native/parity.test.ts -t "<slug>"
npx tsc --noEmit -p tsconfig.json
npx eslint src/t2qcal/lib/native/<category>.ts
```

All six cases per slug must pass. If a value cannot be matched, say exactly which
label/case and why — do not loosen the test.
