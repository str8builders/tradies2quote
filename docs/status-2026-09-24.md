## Fixed
- **Security:** supplier price lookup could fetch internal addresses (SSRF) — now public addresses only, redirects re-checked, size capped (`src/lib/net/safeFetch.ts`). HSTS header. Public logo/avatar buckets limited to images ≤ 8 MB. Account deletion now purges every storage bucket.
- **Privacy:** policy and consent named the wrong AI provider; now Anthropic (text, drawings, supplier quotes, chat) and OpenAI (voice, job photos). Consent version bumped. Photos are re-encoded before any AI call so GPS/EXIF never leaves the server. iOS consent gate on photo-plan and supplier-quote routes.
- **Quote lifecycle:** accepted/scheduled/completed quotes are locked in the app and by a database trigger (SQLSTATE 55000); quotes carry a `version`, and accepting an out-of-date version returns `quote_changed`; `accept_quote` guards restored (sent/viewed only, valid total, agreed figures from the row); stale public PDFs re-render; regenerate is draft-only; public chat uses stored history; invoice PDF markup breakdown; invoice due date restarts on first send.
- **Calculation after transcript:** day/lot labour no longer priced as hours; $0 labour/other lines need acknowledgement before sending; model output whitelisted; library matching checks size and unit (5.4 m ≠ 2.4 m); tradie's default terms kept; transcript cleaned before pricing (raw kept); quote checker runs on every quote with the real tax rate and markup; exact half-up rounding; tax label/rate by country.
- **Supplier quote scan and CSV import:** printed line totals used (10,000 × $0.05 = $500, GST-inclusive lines exact); duplicate photos/pages counted once; CSV decimal commas, POA/blank prices, "(5.00)", metadata wipe and position-based learning fixed; drawing scan waits long enough and retries once on overload; plain-English errors.
- **Drawing takeoff:** bare numbers of 100 or more in a length, height or width are millimetres ("GIB both sides for a 10 m wall, 2400 high" was 18,334 sheets / 806,697 screws, now 19 / 836); values still out of range are flagged and never calculated; scan-review corrections (wall run 40 → 52 m, deck width 4.8 → 5.4 m) now reach the takeoff; plain scan errors; the phone waits 300 s and says "Still reading the drawing" after 30 s; float-safe round-ups (plates, screws, concrete); NZ rules: a dwang row per 1.35 m of stud height, skirting stops at doors, architraves on every lined face.
- **Plan reader:** "Revision: B" read as "isio" and "Rev 1: 20/08/2026" read as a 1:20 scale — fixed (feature is owner-only and unused so far).
- **Performance:** framer-motion removed from the app header/menu, video player lazy-loaded, settings fetched in parallel, list pages select only the JSON fields they show, three indexes.
- **Monitoring:** daily error digest never sent (environment fell back to "development") — fixed; exploit-scan and browser-extension noise filtered; tokens and ids scrubbed from reported paths; stale-deploy detection covers Next 16 messages.

## Decisions and what was done
- **Password reset in any browser:** reset emails used GoTrue's PKCE code link, which only works in the browser that asked (home-screen app → Safari failed). Templates now link to `https://tradies2quote.com/auth/confirm?token_hash={{ .TokenHash }}&type=recovery`; the page verifies with `verifyOtp` on POST, so Outlook/Mimecast link scanners can't spend the token. One PKCE test email was sent to the owner account (`challis836@gmail.com`) on 24 Sep 19:31 NZST for the owner to tap on a different device.
- **Email confirmation on, phone sign-up off:** `/srv/t2q/supabase-official/docker/.env` now has `ENABLE_EMAIL_AUTOCONFIRM=false`, `ENABLE_PHONE_SIGNUP=false`, `ENABLE_PHONE_AUTOCONFIRM=false`, plus `MAILER_TEMPLATES_{RECOVERY,CONFIRMATION}` and subjects, wired into `docker-compose.yml` (auth service). Backups: `*.bak-auth-links-20260924`. Recreated with `docker compose up -d --no-deps auth`; `/auth/v1/settings` shows `mailer_autoconfirm: false`, phone off. All 3 existing accounts were already confirmed.
- **Stripe:** there was no duplicate endpoint. The account (shared with Scoriq, STR8 Hub, stoweapp and a Supabase function) has one active Tradies2Quote endpoint, `we_1Tu47uRxqdsv0POMQzkB00HH` → `/api/stripe/webhook`, and every delivery (4, 13–14 Sep) returned 200. The four "No signatures found" reports (12–20 Sep) were forged/test requests; the group is resolved and the message now names both causes. The app's key is a restricted `rk_live` without webhook/event read, deliberately.
- **Old database copies:** `t2q_release_audit_20260913` and `t2q_native_rehearsal_20260921` dropped (no connections, no timers; only one-off test scripts referenced them).
- **Unpriced materials:** by design (`PRICES_OFF`, owner commit 01f5c08, 7 Jun: count-first, no auto-pricing). No past quote had a priced material line to backfill. Learning on save already works (`applyMaterialCorrections`); the dashboard card now counts priced items and stays until 8 are saved.
- **Barcode scanning:** built from scratch (none existed). "Scan barcode" in the material library and the quote editor (hidden on locked quotes via `isQuoteLocked`). A code already in the tradie's library shows the item and price with one tap to add or open; a new code asks for name, unit and price ex GST (with an includes-GST box) and saves it with the code; an existing item can be picked instead. No outside product database. Decoding uses the phone's BarcodeDetector where it reads retail codes (Chrome on Android), otherwise `barcode-detector` 3.2.2 / zxing-wasm 3.1.3 served from `/vendor/zxing/3.1.3/` (copied and SHA-checked by `scripts/copy-zxing-wasm.mjs` at prebuild; one-year immutable cache; skipped by the proxy). Photo and typed-number fallbacks are always on screen. UPC-A and UPC-E are stored as 13-digit EAN so every reader matches. Migration `20260925_materials_barcode.sql` was dry-run in a rolled-back transaction, then applied and tracked. Not yet tried with a real phone camera. Release with `npm run build` (not `next build`) so the wasm is copied.
